# تغییرات نسخه 4.6.2 — سخت‌سازی همزمانی و چرخه حیات

## هدف این مرحله
کاهش ریسک خرابی دیتابیس، استفاده از اتصال دیتابیس پس از بسته‌شدن Activity، تداخل Backup/Restore و ارسال UI update بعد از پایان چرخه حیات Activity.

## اصلاحات اصلی
- تمام عملیات پس‌زمینه MainActivity از مسیر واحد `submitIo()` عبور می‌کنند.
- ارسال نتیجه به UI از مسیر واحد `postUi()` انجام می‌شود و پس از پایان چرخه حیات Activity اجرا نمی‌شود.
- در `onDestroy()` دیگر دیتابیس بلافاصله در حالی که عملیات I/O ممکن است در حال اجرا باشد بسته نمی‌شود؛ ابتدا Executor به‌صورت graceful متوقف و عملیات در حال اجرا drain می‌شود، سپس دیتابیس بسته می‌شود.
- در صورت طولانی‌شدن غیرعادی عملیات، `shutdownNow()` به‌عنوان مسیر پشتیبان استفاده می‌شود و دیتابیس فقط در صورت پایان Executor بسته می‌شود تا Race خطرناک ایجاد نشود.
- عملیات Backup/Restore در سطح فرآیند با یک Lock مشترک سریال شدند.
- کپی دیتابیس در مرحله staging و fallback نصب Restore از مسیر `copyVerified()` عبور می‌کند.
- از شروع چند Backup هم‌زمان جلوگیری شد؛ همچنین هنگام انتظار برای انتخاب محل ذخیره Backup، Restore مسدود است.
- اگر ذخیره Backup در مقصد SAF خطا دهد، فایل Backup موقت حذف نمی‌شود و امکان انتخاب دوباره مقصد فراهم می‌شود.
- import اضافی `MessageDigest` از BackupManager حذف شد.
- تست QA جدید `tools/qa_concurrency_hardening.py` اضافه شد.

## وضعیت آزمون
تمام QAهای پروژه در این مرحله PASS شدند:
- preflight
- migration
- persistence
- reminder hardening
- adversarial
- backup/restore
- concurrency hardening
